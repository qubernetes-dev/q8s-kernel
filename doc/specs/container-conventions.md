# Container conventions

Status: Draft

## Scope

These conventions cover the workload images generated by q8s and the runtime contract for images supplied with `--image`. The installed execution target plugin selects the base image. q8s adds the project's Python dependencies and provides the workload files when it creates the Kubernetes Job. [Execution target plugins](../adrs/0004-entry-point-based-execution-targets.md)

## Workspace folder

- Generated Dockerfiles set `WORKDIR /app`. The target plugins mount the workload ConfigMap read-only at `/app` and preserve the workload's relative file paths. [Workspace constant](../../packages/q8s/src/q8s/constants.py#L5) · [Pod template](../../packages/q8s/src/q8s/plugins/job.py#L36)
- Workload source files arrive through that mount. Keep Python itself and the installed dependencies available outside the mounted workspace so they remain accessible at runtime.
- Custom images must support the read-only mount at `/app`. Use `/app` as the working directory when workloads rely on relative paths. q8s's target plugins inherit the image's working directory.

## Interpreter

- The Job invokes `python` on `PATH`. Dependencies installed during the image build must be importable by that interpreter. A custom image must provide both the interpreter and the dependencies its workloads need. [Job command](../../packages/q8s/src/q8s/plugins/job.py#L36)
- `Q8Sproject.python_env.python_version` defaults to `3.12`. q8s passes this project-level value to the selected target plugin when generating the Dockerfile. The `hpc-rocm` exception is listed below. Target-specific `python_env.dependencies` add packages to the common `python_env.dependencies` list. [Project configuration](../../packages/q8s/src/q8s/project.py#L76) · [Requirements generation](../../packages/q8s/src/q8s/project.py#L422)
- An ordinary workload runs as `python /app/<entry-script>`. A `src/` workload runs as `python -m package.module` with `/app/src` on `PYTHONPATH`. q8s appends workload arguments after the script path or module name. [Project `src/` layout decision](../adrs/0003-project-src-layout.md) · [Command and arguments](../../packages/q8s/src/q8s/plugins/job.py#L36)

The current module-name calculation can include an extra `src.` prefix. For example, it can emit `src.package.module` for `src/package/module.py`, where the specified module name is `package.module`. [Current module-name calculation](../../packages/q8s/src/q8s/workload.py#L90)

## Base and application images

| Target | Base image selected by the current plugin |
| --- | --- |
| `cpu` | `python:<python_version>-slim`. [CPU plugin](../../packages/q8s/src/q8s/plugins/cpu_job.py#L16) |
| `gpu` | `ghcr.io/qubernetes-dev/cuda:12.8.1-r2-py<python_version>`. The tag includes the CUDA version, image revision, and Python version. [CUDA plugin](../../packages/q8s-cuda/src/q8s_cuda/cuda_job.py#L23) |
| `hpc-cpu` | `python:<python_version>-slim`. [HPC CPU plugin](../../packages/q8s-hpc-cpu/src/q8s_hpc/hpc_job.py#L140) |
| `hpc-rocm` | `aapopeiponen/qiskit-lumi-rocm-singlenode`. This fixed reference has no explicit tag. The plugin ignores `python_version`, so the selected image determines the interpreter version. [HPC ROCm plugin](../../packages/q8s-hpc-rocm/src/q8s_hpc_rocm/hpc_rocm_job.py#L142) |

The base image supplies the interpreter, `pip`, and any runtime libraries provided by the target. q8s generates one application image build context per configured target in `.q8s_cache/<target>/`. The generated `requirements.txt` lists common dependencies first, followed by target-specific dependencies. The Dockerfile starts with the selected `FROM` and adds OCI metadata labels and the following build instructions. [Build context generation](../../packages/q8s/src/q8s/project.py#L159) · [Dockerfile generation](../../packages/q8s/src/q8s/project.py#L448)

```dockerfile
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache -r requirements.txt
```

The direct Docker build and the generated `.q8s_cache/docker-bake.json` both select `linux/amd64`. [Direct Docker build](../../packages/q8s/src/q8s/project.py#L241) · [Bake generation](../../packages/q8s/src/q8s/project.py#L436)

## Verification

| Scenario | Expected result |
| --- | --- |
| Generate a CPU image with the default Python version | The Dockerfile starts with `FROM python:3.12-slim` and sets `WORKDIR /app`. |
| Generate images with both common and target-specific dependencies | Each build context contains a `requirements.txt` with the common dependencies followed by that target's dependencies. |
| Generate a GPU image with Python `3.12` | `FROM` uses `ghcr.io/qubernetes-dev/cuda:12.8.1-r2-py3.12`. |
| Build directly or with the generated Bake file | The build targets `linux/amd64`. |
| Run an ordinary script | The Pod mounts `/app` read-only and invokes `python /app/<entry-script>` with the supplied arguments. |
| Run a `src/` workload | The Pod sets `PYTHONPATH=/app/src` and invokes `python -m package.module`. The current naming gap above affects this scenario. |
